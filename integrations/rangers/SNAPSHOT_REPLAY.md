# Snapshot replay compatibility

The snapshot pair `(career, source_sha256, selection_sha256)` identifies the input save and filter bytes, not a globally unique import event. In the old schema a same-game-date A → B → A sequence could fail when the latest player hashes changed back to A, because A already had a historical snapshot. Advancing the game date still rejects older rotating saves, as before.

On open, the watcher automatically migrates the legacy inline UNIQUE constraint to a nonunique lookup index. The SQLite migration uses a write transaction (`BEGIN IMMEDIATE`), copies only the snapshot table with its original IDs and values, preserves explicit indexes and triggers, and checks foreign keys before committing. FK enforcement is suspended only on the migration connection and restored afterwards. On failure, SQLite rolls back the table replacement and leaves historical data intact. The migration is detected by the schema and is safe to run again. No database deletion, rebuild by the user, or data re-import is needed. Other tables and references are not rewritten. An older watcher cannot safely replay differing observations against an unmigrated database; use the updated watcher. Once distinct replay events exist, reverting to a unique pair schema would require dropping legitimate history, so no destructive down migration is offered.

On import, the existing `BEGIN IMMEDIATE` serialises the chronology check and player state comparison with writes. If the selected observations differ from `player_latest`, append an immutable snapshot event with the original hashes and only the changed player versions, even when the pair occurred before. `id` disambiguates distinct events on the same game date. Prior snapshots, dates, timestamps and player versions remain unchanged. Point `player_latest` to the newly observed version. If the observations are identical, append no snapshot or player versions; still reactivate the exact selected cohort and update the existing chronology/benchmark metadata under the same transaction. A second concurrent watcher observing that state adds no duplicate revision. Failure at any stage rolls back the snapshot, versions, latest pointers, cohorts, chronology and benchmark writes together.

The replay semantics intentionally retain actual A → B → A state transitions, rather than silently overwriting A or pointing the latest state backwards through history. An unchanged immediate repeat is idempotent. The bridge and scoring, assessment, benchmark and simulation contracts are unchanged.
