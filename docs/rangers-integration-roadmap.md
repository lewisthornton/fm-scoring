# Rangers integration audit and development plan

Reviewed on 19 November 2026 against the integration branch and upstream main at `00a68ce`. The integration is one commit ahead of both the fork's main and upstream main. Its diff adds two scripts and extends the ignore rules. It adds no tests or CI workflow.

## What works today

1. The watcher waits for stable input, copies the save into a temporary directory, and runs `fmsave info` and a managed-club player export against the copy. With F9 candidates it also exports the world temporarily to resolve identities. It matches by ID or by name, age, club and corroborating attributes, and refuses low-confidence wholesale cohort replacement.
2. The SQLite transaction records changed player payloads and separately refreshes current squad and target membership. A player can belong to both. Version storage is scoped to the selected players. The default career and managed-club labels assume Rangers.
3. The bridge opens SQLite with `mode=ro`, joins current membership to the latest record, normalises attributes including goalkeeper spellings, and reads `weights/fm27v2.toml`. It calculates weighted scores and positional familiarity locally, writes dated outfield/GK observations and `last_batch` into a dedicated save slug, publishes recruitment HTML and invokes `score.py --save <slug>`. A squad player who is also a target is exported only as squad. Same-day empty cohort files are removed. An incomplete GK record aborts the build.
4. Upstream independently reads those observations, scores players and renders seven native pages. It also supports screenshot observations and a separate full-world import. Preserve both paths, the bridge CLI, existing SQLite databases, GK handling, local output locations and existing weight defaults.

A scratch smoke check passed invented rows through the actual watcher transaction, read-only bridge, CSV writer and native CLI. Two squad players (one GK) and one target produced eight HTML files. It used no live save, F9 plugin or fmsave executable. File generation was verified, not browser interaction.

## Technical debt in priority order

| Priority | Source and behaviour | Consequence |
| --- | --- | --- |
| 1 | `watcher.import_selection` compares incoming dates to `MAX(snapshots.game_date)`, but writes a snapshot only on player changes. In a synthetic sequence 1 Jan → 3 Jan unchanged → 2 Jan unchanged, active membership ended at 2 Jan. | A rotating save can rewind the cohort and the dashboard date. Store the last accepted game date per career independently of attribute changes, in the same transaction. Preserve same-date filter swaps. |
| 1 | `bridge.native_rows` marks every on-loan squad member as out. Upstream `import_save` checks the parent club UID. `choose_rows` checks nonempty squad and required columns without verifying that the managed club is Rangers. | Loan availability and the identity of the imported club need verification before a depth chart or XI can be trusted. |
| 1 | SQLite keys are stable within a career, but `score.load_players` groups CSV rows by display name. `bridge.get_database` adds UID suffixes only while duplicate names coexist in the active set. | The same player's history can split when a namesake enters or leaves. Supply identity through a backward-compatible observation contract. A new numeric column alone would be interpreted as an attribute by the current reader. |
| 2 | `bridge.score` duplicates `score.weighted`. `POSITION_CODES` collapses left/right and lets MC qualify for both 6 and 10. A new weight key has no mapping and can trigger a lookup error. Native squad position ratings come from a world file, which the bridge explicitly refuses in its slug. | Dashboard and native views can disagree about eligibility. The best attribute score and the in-game suitability for a chosen role answer different questions. |
| 2 | `dashboard_data` subtracts the best familiar incumbent's weighted role score. Upstream separately computes outfield `win_score` and goalkeeper `pts_score`. The outfield function sums available attributes, so comparisons with different coverage can mislead. | The existing uplift is in role-score units. A multi-slot incumbent can be counted several times, and role-score uplift cannot be read as extra wins. |
| 2 | Native charts can default to the configured division. The bridge exports neither a managed division nor reference populations. Upstream's world charts target coded English divisions. A shortlist is a selected sample. | Rangers can land on an unrelated comparison league. A Scottish competition identifier and a reference distribution are two separate inputs. |
| 2 | The bridge publishes recruitment and updates observations/config before calling the native CLI. Individual replacements do not make the generation atomic. A slug containing an existing world is protected, but another existing observations-only slug can still have its config edited. | Renderer failure can leave pages from different runs. Introduce explicit output ownership and staged publication with retry tests. |
| 3 | Versions preserve attribute changes, while membership rows retain only current state and last seen date. The bridge reads the latest rows, so periods when it was offline are absent from native observations. | Historical charts should query versioned observations by game date. Historical eligibility needs dated cohort events going forward. |

## Consolidated architecture

Keep the two commands as adapters. The watcher alone handles save-copy I/O, F9 matching and writes to the scoped database. Add a read-only repository that returns career, game date, stable player key, attrs, per-position evidence, cohort and provenance. A CSV adapter continues to accept upstream's legacy files. Keep observed FM role suitability optional, scoped to player, position, phase, role and date. Store its source and scale. Until a supported export supplies it, show “unknown” and keep any computed role fit separately labelled.

Extract upstream's pure weighted, curve, win and GK points functions into one importable Python module. Retain existing public functions and CLI. Separate the profile catalogue from a save's chosen formation slots and from page generation. Feed the native pages and recruitment dashboard a shared scored result. Keep the CSV writer during migration. Where full-world pages score in JavaScript, use shared test vectors to check parity. Preserve score units, input coverage and model version on every result. Keep user data local. Use only invented fixtures in the repository and CI.

## Review sequence and acceptance criteria

Each numbered item is a separate candidate PR. Split a UI change from its underlying data contract if either diff becomes difficult to review.

1. **Characterisation tests and CI.** Use standard-library tests, a temporary directory, invented CSV/SQLite inputs and a fake fmsave boundary. Run the real bridge and upstream CLI. Assert eight page paths, actual roster/target identities, last batch, GK spelling and weighted parity, incomplete-GK failure, ambiguous F9 matches, overlapping cohorts, empty targets and idempotent reruns. Test Windows and Linux, starting with Python 3.11. Assert source-copy integrity and absence of persistent world data. Keep behavioural fixes separate.
2. **Career chronology.** Reproduce the three-date rewind, fix the per-career watermark with backward-compatible initialisation from existing evidence, and verify same-date A → B → A filter switches and rollback on failure.
3. **Club identity and loans.** Verify managed-club metadata before committing a cohort, derive in/out from ownership, and define default XI availability. Cover incoming, outgoing, unknown and wrong-career fixtures.
4. **Shared scoring.** Move the existing formulas behind a pure API. Compare outfield, GK, missing input and interpolation boundaries against frozen vectors and existing rendered outputs. Keep legacy scoring defaults.
5. **Stable observation identity.** Carry watcher keys and position evidence to native pages without changing the meaning of old screenshot CSVs. Test namesakes, transfers and changing cohorts across dates.
6. **Configurable tactic.** Define slot IDs, side, accepted FM positions, optional IP/OOP roles and phase weights. Ship the existing groups as the default. Verify two formations, repeated CB slots, asymmetric full-backs, custom labels and invalid configs.
7. **Familiarity and suitability.** Retain numeric FM position evidence and legacy text fallback. Display observed role suitability, computed IP/OOP fit and unknowns separately. Test a natural left-back who is unfamiliar on the right and a familiar player with poor role fit.
8. **League benchmark detection.** Resolve managed first-team competition and season from save metadata/tables, reusing upstream club–competition joins. Aggregate position/role distributions during temporary extraction or consume an appropriate reference export. Store aggregates, source, date and sample size. Exact league first, clearly labelled reputation-peer fallback only with sourced comparable data, otherwise show unavailable. Keep a manual override. Test Rangers in Scotland, promotion and thin samples.
9. **XI assignment.** Optimise eligible player-to-slot assignment with one player per slot and one slot per player. IP/OOP roles belong to the same player. Define the objective and deterministic tie-break, allow vacancies and exclude unavailable players. Validate the optimiser against exhaustive search on a small fixture where greedy selection loses.
10. **Weakness and depth.** Show starter, eligible deputy, league percentile or gap, and loss if the starter is removed and the XI is re-solved. Include a fixture where one utility player is the sole cover on both sides. Show unfilled slots and missing benchmarks explicitly.
11. **Signing simulations and rankings.** Solve the same XI before and after adding each candidate. Return changed starters/roles, displaced player, coverage and marginal experimental outfield win-index gain. Keep GK comparisons in GKpts, apply the same eligibility policy to both squads, and disclose the objective used. Test an indirect upgrade through reassignment, a bench-only signing with zero XI gain and incomplete evidence. The index has no calibrated conversion to match-win probability.
12. **Player development.** Read dated player versions by career and key, distinguish observation dates from carried-forward values and persist future cohort changes. Compare scores under a fixed model or mark model changes. Test gaps, transfers and two players with the same name.
13. **Model validation.** Record model/profile version and pre-match predictions with available result, lineup and competition context. Use chronological held-out fixtures, compare against a simple baseline and report sample size and uncertainty. Evaluate ranking usefulness first. Only publish probability estimates after separate out-of-sample calibration; observational results alone do not identify a signing's causal effect.
14. **Reliable publication.** Stage a complete generation, validate it, then publish to a bridge-owned destination. Test renderer failure, interruption and retry against the prior successful generation. Bring this PR forward if publication work starts earlier.

The first implementation milestone is PR 1. Its exit condition is one CI command proving that an invented managed squad and filtered targets still reach both renderers with the expected identities and scores. PR 2 is the first behavioural correction.
