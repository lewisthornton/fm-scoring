# Native position benchmark follow-up

The existing seven profile-group populations mix native positions, so e.g. profile `10` contains MC and AMC. These are explicitly labelled `reference_population=profile_group`; never label a broad comparison as MC-specific. The dependent benchmark change will retain broad comparisons for compatibility, aggregate exact native-position/profile pairs using the same inherited weights and first-team population/quality gates, and expose a separate keyed comparison set. Consumers will join using the actual selection position plus profile, not eligibility alternative or phase. Insufficient native samples must remain unavailable rather than falling back to a broad percentile. Cache provenance must reject pre-native aggregates and preserve independent competition/season detection. Tests will verify disjoint MC/AMC populations, shared inherited profile weights, native evidence and quality thresholds, and XI/depth/signing joins. No scoring recalibration or UI redesign.

Implemented in the dependent PR: reference `native_profiles["profile:position"]`, `native_comparisons` keyed by `(player_id, profile, native_position)`, `native_league_context` in signing reports. Broad profiles/comparisons remain separately available and tagged. Cache policy 5 forces re-extraction of older caches, including those with unavailable histograms. Formation validation requires a supported inherited profile for the selection position; phase and relaxed alternate codes remain independent.
