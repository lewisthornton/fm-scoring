# Squad depth and vulnerability (version 1)

The bridge publishes `squad_depth.json` and `squad_depth.html` alongside `optimal_xi.json`. The XI view links to the depth view; recruitment and native dashboards are unchanged. Everything is computed from the same scoped in-memory assessment and benchmark snapshot, never from hypothetical changes to SQLite or the save.

## Baseline and scenarios

The report embeds the exact existing optimal-XI report as `baseline`. `build_squad_depth(formation, assessment, benchmark=None, *, optimizer, policy=None, baseline=None)` accepts the existing selected-checkout optimizer module and optionally the already solved baseline (if omitted, it solves once). Each baseline starter is removed independently by stable player ID using `build_optimal_xi(..., excluded_player_ids=(id,))`. The optional exclusion iterable filters a local player list, rejects unknown IDs and leaves the default XI contract and policy unchanged. It can also support multiple exclusions in future callers, but this report only simulates single starter losses.

All scenarios must match the baseline career, game date, model, formation and policy and preserve declared slot order. The exact objective remains maximum filled slots, maximum outfield attribute score and independently best goalkeeper score. The implementation asserts that removing a player cannot improve the lexicographic objective; outfield comparisons use exact binary-rational sums like the original solver. Missing goalkeeper totals and score differences remain null, never zero. A loss of completeness dominates any numeric score loss. Scores are separate by domain, and scenarios sort by filled slots lost descending, then outfield before goalkeeper within that group, then loss within the relevant domain, then declared slot order. This is presentation ordering, not a combined vulnerability metric.

`starter_loss_scenarios` contains removed identity/name and original slot, baseline and after totals/filled slots, score and completeness losses, effective deputy, complete ordered assignment references, changed assignments, promoted players, moved starters, newly vacant slots, warnings and monotonicity verification. Each assigned `(slot_id, player_id)` refers to an eligible edge in `coverage`, which retains the full tactical assessment and relevant benchmark context. Changes include stable-ID tie-break swaps, which need not indicate additional tactical necessity. A previously incomplete baseline is compared with its actual cardinality, not a fictional complete XI.

## Coverage

`coverage` is in formation order. Eligible edges reuse the XI eligibility predicate and effective policy verbatim. Each edge contains identity, name, availability, loan state, baseline slot, weighted score, accepted position and phase evidence, unknown role suitability, missing evidence and optional benchmark comparisons. Baseline starters and after-scenario deputies are looked up from this same edge set. `direct_deputy_ids` are eligible non-starters in descending score then stable ID order; `effective_deputy_id` is the actual assigned replacement after exact reoptimisation, potentially a moved starter. A slot can receive an effective deputy while another slot becomes vacant; `maintains_completeness` and `cannot_maintain_completeness_slot_ids` distinguish that case. Vacant baseline slots have no incumbent-loss scenario. Rejected squad edges carry explicit reasons; target-only exclusions are in the embedded baseline.

`exclusive_direct_deputy_ids` are bench players eligible for just that slot; `shared_direct_deputy_ids` have other possible slots. `cover_type` distinguishes none, exclusive, shared only and mixed. `shared_cover` lists pairs with overlapping bench identities and exact simultaneous capacity for those two slots, at most two. `versatility` lists eligible players (including starters) with multiple possible slots, and slots for which each is sole direct bench cover. `bench_only_matching_capacity` counts the maximum number of distinct slots that can be covered by distinct bench players; it reuses the exact assignment solver with zero weights and is a capacity statistic, not a bench-selection recommendation or multi-injury simulation. `bench_cover_dependencies` records the capacity without each bench player and which direct-cover slots become uncovered. Thus a utility player may have zero immediate starting-XI impact but substantial cover value. No player is counted twice in simultaneous capacity.

## Context and format

Root version, career, game date, formation/model hashes, policy and objective match the baseline. `summary` includes cardinality, baseline vacancies, no direct cover, no effective deputy and loss-of-completeness slots. `limitations` describes interpretation and unsupported evidence. League context uses the XI's existing career/date/model/freshness validation and joins stable player/profile; each eligible edge has nullable comparison and reason, including sample size, contributing clubs, competition/season, percentile, median difference and warnings when available. League data is never an objective coefficient. The JSON does not duplicate the large tactical edge records for every hypothetical assignment. Outputs are deterministic, JSON-ready and independent of input order; the builder returns detached data without modifying baseline, assessments or cached benchmarks.

The HTML offers the baseline, direct and effective cover, league percentile context and scenario details in vulnerability order, plus overlap and uncertainty summaries. It is escaped static HTML. Legacy dashboard failure behaviour (e.g. incomplete GK attributes) remains unchanged while the independent XI and depth views report what is feasible.

These are uncalibrated attribute-based squad vulnerability diagnostics, not injury forecasts, match-win predictions or a measured tactical role model. Available means squad/loan status, not match-day fitness, injury, suspension or registration. Missing scores/familiarity are not zero. No transfers, fees, wages, reweighting or live database writes are performed.

## Verification

Invented fixtures cover complete and partial teams, both formations, duplicate CB positions, a multi-starter chain beating the highest direct deputy, shared/sole cover, GK loss, loans, cohort/threshold/category/unknown rules, incomplete attributes, phase warnings, benchmarks and staleness, ties and provenance, independent exclusion solves and input immutability. Integration tests retain existing frozen native/recruitment payload hashes, scoped career isolation, read-only DB behavior and standalone launcher compatibility. No personal saves or manual FM simulations are used.
